# CUJ-APEX-020 sample

## Description

Sample demonstrating CUJ-APEX-020, as defined
[here](https://docs.google.com/presentation/d/1RPAbeF570Wzaf1qlrnQgMTi3RzFrm6Tw/edit#slide=id.p11)
That is, sample demonstrates:

1.  Setup: service bundle installed on the system, which exposes diagnostics
    routine with Routine ID 1. DiagnosticsManager implementation is also
    installed. DiagnosticsManager can discover the routine defined in the
    service bundle.
2.  Service bundle gets updated to a newer version. New version modifies
    diagnostic declaration: -- routine with Routine ID 1 has a different
    definition: a new protobuf message is returned -- a new routine is added,
    with Routine ID 2.
3.  Sample demonstrates that, by solely updating the service bundle, without
    DiagnosticManager or VM-config updates, DiagnosticManager discovers the
    newly declared diagnostic definition, from the new version of the service
    bundle.

## Sample execution

### Build image and start VM

```bash
m installclean && m
cvd start
adb wait-for-device && adb root
```

### Launch diagnostics reporting service bundle

```bash
adb shell sdv_service_bundle start instance1:com.sdv.google.sample.diagnostics_update.UpdatableDiagnosticsBundle/instance1
```

### Inspect DiagnosticManager logcat output

Inspect logcat output for following line, proving that the DiagnosticManager
sample implementation correctly detects the diagnostic declaration from version
1 of bundle:

### Build v2 of the diagnostics service bundle

```bash
m com.sdv.google.sample.diagnostics_update.v2
```

Build output, the built apex, should reside in:
`${ROOT_DIR}/out/target/product/sdv_core_cf/product/apex/`

### Update service bundle to v2

For additional information and debugging tips, see update manager sample, and
the detailed
[README](../../../../core_services/samples/update_manager/README.md)

Run:

```bash
adb root
```

```bash
adb mkdir data/mydir
```

```bash
adb push <${ROOT_DIR}/out/target/product/sdv_core_cf/product/apex/com.sdv.google.sample.diagnostics_update.v2.apex /data/mydir/
```

```bash
adb shell /apex/com.sdv.google.sample.update_manager.client/bin/sdv_update_manager_client \
  prepare service-bundle \
  --boot_attempts 2 \
  --apex_path /data/mydir/com.sdv.google.sample.diagnostics_update.v2.apex
```

```bash
adb shell /apex/com.sdv.google.sample.update_manager.client/bin/sdv_update_manager_client activate
```

```bash
adb reboot
adb wait-for-device && adb root
```

### Launch diagnostics reporting service bundle post update

```bash
sdv_service_bundle start com.sdv.google.sample.diagnostics_update.UpdatableDiagnosticsBundle
```
